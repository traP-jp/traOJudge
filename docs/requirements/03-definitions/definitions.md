# 定義

| 用語 | 意味 |
| --- | --- |
| 問題 / problem | 作問・公開・提出・採点の対象。テストケースや judge-definition に関係する |
| 提出 / submission | 利用者が問題に対して送るソースと、それを識別する記録 |
| ジャッジ実行 | 提出を判定し、得点・実行結果を報告する処理。再ジャッジは新たな実行として扱う設計がある |
| ジャッジ定義 / judge-definition | 問題をどう採点するかを定める再利用可能な定義。処理の依存関係や実行条件を持ち、個別の提出内容は含まない。problem-owner や tester が管理する |
| ジャッジ実行要求 | 一回のジャッジ実行を依頼する情報。使用するジャッジ定義、提出固有の入力、実行を識別する情報からなる |
| 実行手順 | ジャッジ定義に提出固有の入力を適用し、その一回の実行内容を具体化した手順。APIサーバーが組み立てる |
| 言語ID | UI・CLI・Back・Judgeで共有する、提出言語を識別するサービス共通のID。Backが受け付けたIDをそのままJudgeへ渡す |
| Writer / writer | 問題を作成できる利用者・ロール |
| problem-owner | 特定の問題を所有し、更新・削除や judge-definition などを管理するロール |
| tester | 特定の問題の読み取り・更新、再ジャッジなどに関与するロール |
| standard-user | 自己登録後に取得する基本ロール。公開問題への提出、解説投稿、virtual-contest 作成などができる |
| contest | 運営者が問題・ルール・開催時間を設定する通常コンテスト |
| virtual-contest | 公開問題を用いて standard-user が作成できるコンテスト |
| contestant | 特定の通常コンテストに参加するロール |
| Clar | コンテストに対する参加者の問い合わせと運営者の回答 |
| editorial | 問題の解説。投稿者が編集できる |
| マジックリンク | メールで送付するリンクを用いた、パスワードを使わない認証方式 |
| 基盤の差し替え | DB・ストレージ・キューなどの提供サービスや実装を後から変更すること |

共有用語の定義は[用語集](../../domain/GLOSSARY.md)、権限の詳細とスコープは[ロール定義](../../domain/role.md)を参照する。`ICPC形式` と `AtCoder形式` は、本書では同得点時の比較方式を区別する名称として使う。
