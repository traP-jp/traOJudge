# 前提条件および依存関係

## 依存関係

| 依存先 | 必要になる理由 | 状態 |
| --- | --- | --- |
| neoShowcase | WebUIの配置先 | 配置方針として採用 |
| AWS | API・DB・ジャッジ基盤などの配置先 | 採用方針。具体的なスタックは未決 |
| DB | 利用者・問題・提出・結果などの永続化 | PostgreSQL互換を優先 |
| S3 | 提出ソース・作問ファイルの保管 | 採用方針 |
| SQS | ジャッジ要求・結果の受け渡し | 採用方針 |
| メール配送基盤 | マジックリンクを利用者へ届ける | 必要。具体的なサービスは未決 |
| traQ・Google・GitHub | 外部認証先として3つとも提供する | API（Back）が認可URL作成・認可情報の検証・利用者への紐付け・セッション発行を担当する。外部認証を完了できない場合は認証失敗として扱い、利用者やセッションを作成しない |
| CLI | コマンドラインからの問題登録 | 専用APIを開発者トークンで利用し、発行された署名付きURLでS3へ直接アップロードする |
| TraoPy | 既存構成図にあるWriter向けのファイル登録ツール | CLIの実装として採用するかは未決 |

## 既存資料から変更する点

- 既存構成図のAPI・DB配置はneoShowcaseだが、要求上の配置先はAWSとする。
- 既存DB設計の提出ソース本体のDB保存は採用せず、S3へ保存する。
- 既存APIのメールアドレスとパスワードによる認証は、パスワードを使わないマジックリンク方式へ変更する。
- 開発用DB設定はMariaDBだが、DBの方針はPostgreSQL互換を優先するものとする。
- 既存UIにはneoShowcase経由のtraQログインがあるが、新しい外部認証フローではAPI（Back）が外部サービスとの認証処理を担い、neoShowcaseは画面表示と認可URLへの遷移を担う。
