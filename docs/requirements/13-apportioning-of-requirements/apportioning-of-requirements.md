# 要求事項の割り当て

要素ごとの主な責務を以下に割り当てる。この分割は、個別のサービス・プロセス・インスタンスを要求するものではない。

## 実装時の専門分野

APIサーバーとインフラは、一つのAWS側システムとして[構成ブロック](../../services/aws-building-blocks.md)へ分解して設計する。下表は実装時の専門分野であり、設計・議論を分ける境界ではない。各ブロックのコード・AWSリソース定義・接続確認をまとめて作業票にし、具体的な入力と出力を決めてから分担する。

| 分野 | 担当範囲 |
| --- | --- |
| UI | WebUIの画面と利用者操作 |
| APIサーバー（Back） | WebUI等のAPIとCLI専用API、サービス側の機能・権限・データ、DAGの解決・実行手順の具体化・実行順序の制御を含むジャッジ制御、結果の解釈と反映 |
| CLI | 問題登録などをコマンドラインから実行し、DAG・使用する実行環境の指定と必要なファイル集合を提供するクライアント |
| インフラ | 配置、DB・ストレージ・キューなどの提供基盤とBackの接続実装、実行環境の定義・構築・配置・運用 |

実装の専門分野はUI・APIサーバー・インフラ・CLIの4分野とする。Judgeはジャッジに関する論理的な機能を指す。ジャッジ制御はAPI側、実行環境周りはインフラ側が実装する。キューで依頼する処理はDAGの実行ノード1つずつとする。プロセス配置と要求・結果の具体的な形式は、構成ブロックB2・B5・B6の接続として議論する。

## 要素への割り当て

| 要素 | 割り当てる責務 | 関連する機能要求 |
| --- | --- | --- |
| WebUI | 閲覧・登録・作問・提出・コンテスト参加／運営の画面。提出ソースは署名付きURLでS3へ直接アップロード・ダウンロード | REQ-PUBLIC-01、REQ-CONTENT-01、REQ-CONTEST-01、REQ-FILE-02〜03 |
| API | WebUI等のAPIとCLI専用APIによる操作受付、入力と閲覧権限の確認を各担当へつなぐ、処理の依頼と結果の返却 | 各機能要求の外部受付、REQ-CLI-02、REQ-FILE-03 |
| 利用者・認証・権限 | 自己登録、基本ロール、マジックリンク認証、開発者トークンの発行・失効、操作権限 | REQ-REGISTER-01、REQ-ROLE-01、REQ-AUTH-01、REQ-CLI-03 |
| 問題・作問・解説 | 問題・テストケース・judge-definition・解説・共同作業の管理 | REQ-CONTENT-01、REQ-ROLE-01 |
| コンテスト・順位 | 通常／virtualの運営・参加・Clar・得点計算と順位 | REQ-CONTEST-01、REQ-SCORE-01〜04 |
| 提出・ジャッジ管理 | Backによる提出確定・実行IDの発行、問題版の固定、DAGの解決・実行手順の具体化・実行順序の制御、提出記録、提出ソースの閲覧権限確認、作問者の登録情報に基づくノード結果の解釈、重複を二重計上しない結果反映、再ジャッジの管理 | REQ-JUDGE-01〜09、REQ-FILE-01〜03 |
| ジャッジ実行基盤 | インフラ担当による実行環境の提供、SQSとS3への接続、指定された処理の実行とノード単位の結果報告。実行基盤からDBへ直接接続しない | REQ-JUDGE-01〜04、REQ-JUDGE-06〜09、REQ-SCORE-01 |
| DB | 構造化データの永続化。提出ソース本体は含まない | REQ-FILE-01と各機能の保存 |
| ファイル保管 | 提出ソースと作問ファイルの実体を保存・提供 | REQ-FILE-01〜03 |
| ジョブキュー | 要求と結果を非同期に受け渡す | REQ-JUDGE-01 |
| メール送信 | 送信キューから要求を受け取りマジックリンクを配送 | REQ-MAIL-01 |
| CLI | メタデータと必要なファイル集合を用意し、専用APIと署名付きURLで登録・アップロードしてAPIへ完了通知 | REQ-CLI-01〜05、REQ-CONTENT-01 |

機能要求の本文は[機能](../14-specified-requirements/02-functions/functions.md)を参照する。

## 複数分野で決める境界

以下は全体の要件整理で優先する項目である。AWS内部の議論は、[構成ブロック間の接続](../../services/aws-building-blocks.md#議論を接続ごとに閉じる)へ割り当てて具体化する。

| 関係する分野 | 決める内容 |
| --- | --- |
| UI・CLI・Back | WebUIとCLIの操作範囲、権限確認、CLIファイル登録の責任分担。外部認証処理はAPI（Back）が担当する |
| CLI・APIサーバー・インフラ | [問題登録・ジャッジ実行の受け渡し仕様](../14-specified-requirements/01-external-interfaces/problem-registration-contract.md)の形式・変換境界、実行環境の指定・ファイル参照、検証、互換性 |
| APIサーバー・インフラ | APIサーバーのジャッジ制御から実行環境へ渡す要求と結果の契約、実行単位と識別、再配信・再ジャッジ時の制御 |
| Back・インフラ | データとファイルの所有・保存、キューの契約、基盤の交換点 |
| 全分野 | 共有する識別子・用語、契約の変更・互換性、結合時の確認責任 |
