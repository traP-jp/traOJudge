# 外部インターフェース

## 接続境界

| 境界 | 目的・受け渡す情報 | 決定状況 |
| --- | --- | --- |
| WebUI・外部クライアント ↔ API | 利用者操作、提出、閲覧、管理操作 | 既存OpenAPIを資料とし、今回の変更を反映する |
| WebUI ↔ API・S3 | 署名付きURLの取得と提出ソースの直接アップロード | APIがURLを発行し、Backが提出確定とジャッジ依頼を担当する |
| CLI ↔ CLI専用API・ファイル保管 | DAG・実行環境・ノード結果の解釈情報を含むメタデータと、全テストケース・テストコード・問題得点計算ロジックのファイル集合 | 専用APIがトークン認証・権限確認・署名付きURL発行を担い、CLIがS3へ直接アップロードしてAPIへ完了通知する |
| API ↔ DB | 構造化データの読み書き | PostgreSQL互換を優先 |
| API → ジャッジ要求キュー | Backが発行した実行ID、固定した問題定義、提出コードのS3参照・提出言語などの実行時情報 | 定義と入力の組を渡し、Judgeが具体化する。各入力の表現とメッセージ形式はTODO |
| Judge → S3（提出コード取得） | 保管先・オブジェクトキー・必要な版情報を用いて対象コードを取得 | Judgeの実行基盤の権限で取得する |
| UI・CLI・Back・Judge間の言語指定 | サービス共通の言語ID | Backが受け付けたIDをそのままJudgeへ渡す。IDの一覧・具体的な表現はTODO |
| Judge → ジャッジ結果キュー | 要求と同じ実行ID、DAGのノード単位の結果 | Backが作問者の登録情報に基づいて解釈する。ノード識別・結果・解釈情報の形式はTODO |
| Backの結果反映処理 ↔ DB | 実行結果と提出の現在状態の更新 | Backが同じ実行IDの同じ結果を一回分として反映する。JudgeはDBへ直接接続しない。残る更新契約はTODO |
| API → メールキュー → 送信処理 | 宛先とマジックリンク送信に必要な情報 | 形式・配送サービスはTODO |
| 認証機能 ↔ 外部認証先 | 認可・利用者情報・アカウント対応付け | 採用範囲・責任境界はTODO |

関連資料は[参照文献](../../04-references/references.md)にまとめる。

ジャッジ定義・ジャッジ実行要求の形式と参照先、Judgeによる実行手順の組み立て、ノード単位の結果とBackによる解釈の分担は[問題登録・ジャッジ実行の受け渡し仕様](problem-registration-contract.md)にまとめる。
