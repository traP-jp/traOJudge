# 機能

## 一般公開・利用者・権限

| ID | 要求 |
| --- | --- |
| REQ-PUBLIC-01 | サービスを一般公開し、非ログイン利用者が公開情報を閲覧できること |
| REQ-REGISTER-01 | 管理者承認なしで登録でき、登録直後にstandard-userとなること |
| REQ-ROLE-01 | [ロール定義](../../../domain/role.md)の機能と操作権限をリリース対象とすること |
| REQ-AUTH-01 | メール認証にマジックリンクを使い、パスワードを使わないこと |

外部認証先の採用範囲と、認証処理をAPI・neoShowcaseのどちらが担うかは未決である。

## 問題・提出・コンテスト

| ID | 要求 |
| --- | --- |
| REQ-CONTENT-01 | 権限に応じて問題・テストケース・judge-definition・解説を作成・管理できること |
| REQ-CLI-01 | 問題登録をコマンドラインから実行できるCLIを提供すること |
| REQ-CLI-02 | CLI専用APIを提供すること。WebUIとCLIの操作APIを共通化することは要求しない |
| REQ-CLI-03 | CLI専用APIを利用者に紐づく開発者トークンで認証すること。利用者自身がトークンを発行・失効できること |
| REQ-CLI-04 | CLIのファイル登録では、専用APIが権限確認と署名付きURL発行を担い、CLIがS3へ直接アップロードしてAPIへ完了通知すること |
| REQ-CLI-05 | CLIが問題登録データとして、DAG・実行環境・ノード結果の解釈情報を含むメタデータと、全テストケース・テストコード・問題得点計算ロジックを含むファイル集合の組を提供すること。ジャッジ定義の詳細は[参照先と接続契約](../01-external-interfaces/problem-registration-contract.md)に基づき具体化すること |
| REQ-CONTEST-01 | 通常コンテストとvirtual-contestの作成・運営・参加、Clar、順位の確認を扱うこと |
| REQ-JUDGE-01 | 提出を受け付け、要求キューを介してジャッジを実行し、結果キューから判定・得点を受け取ること。ロール定義に応じた再ジャッジも扱うこと |
| REQ-JUDGE-02 | 実行基盤はサービスのDBを直接読み書きせず、SQSで要求・結果を受け渡し、必要ファイルをS3から取得すること。ジャッジ制御と結果のDB反映はAPIサーバーが担うこと |
| REQ-JUDGE-03 | Backがジャッジ要求を作る時点で、使用する問題・ジャッジ定義・ファイルの版を固定すること。待機中・実行中の問題更新で要求の実行内容を変えず、更新版を使う場合は別の実行要求とすること |
| REQ-JUDGE-04 | Backがジャッジ要求ごとに一意の実行IDを発行し、Judgeが結果に同じIDを付けて返すこと。再ジャッジは別ID、同じ要求の再配信は同じIDとすること |
| REQ-JUDGE-05 | 同じ実行IDの同じ結果が複数回届いても、Backが一回分として反映し、得点や結果を二重計上しないこと |
| REQ-JUDGE-06 | ジャッジ定義とジャッジ実行要求を区別すること。ジャッジ実行要求には、使用版を固定した問題定義に加えて、提出コードのS3参照・提出言語など実行ごとの情報を持たせること |
| REQ-JUDGE-07 | APIサーバーが固定したジャッジ定義に提出固有入力を適用して実行手順を具体化し、DAGの解決と実行順序の制御を担うこと。実行基盤へはDAGの実行ノード1つずつ処理を依頼すること。実行環境周りはインフラ担当が実装すること |
| REQ-JUDGE-08 | 提出コードをS3のオブジェクト参照（保管先・オブジェクトキー・必要な版情報）で渡し、Judgeの実行基盤の権限で取得すること |
| REQ-JUDGE-09 | JudgeがDAGのノード単位で結果を返し、Backが作問者からCLIで登録された情報に基づいて結果を解釈すること |
| REQ-LANG-01 | 提出言語にUI・CLI・Back・Judgeで共有するサービス共通の言語IDを用いること。Backが受け付けたIDをそのままJudgeへ渡すこと |
| REQ-LANG-02 | 問題ごとに禁止言語タグを設定できること。言語更新後も過去問題の言語制約を維持して提出を継続できる方式とすること |
| REQ-FILE-01 | 提出ソース本体と作問ファイルをS3へ保存すること。提出ソース本体をDBには保存しないこと |
| REQ-FILE-02 | WebUIの提出ソースはAPIが発行する署名付きURLでブラウザからS3へ直接アップロードすること。提出確定とジャッジ依頼はBackが担うこと |

## 得点と順位

| ID | 要求 |
| --- | --- |
| REQ-SCORE-01 | 問題の得点はWriterが作成したジャッジプログラムの報告によること。各問題の提出の最高得点を採用し、その合計をコンテスト得点とすること |
| REQ-SCORE-02 | 順位はコンテスト得点の高い順とし、同得点時だけ、選択されたタイブレーク方式で比較すること |
| REQ-SCORE-03 | ICPC形式・AtCoder形式の2つをサービス側で用意し、contest-setterが選べること。両方式ともペナルティnを指定でき、nは0以上の整数分で、開始前まで変更できること。開始後は固定とすること |
| REQ-SCORE-04 | 各問題の最高得点を初めて得た提出より前の提出をペナルティ対象とし、CE・IE・WEは回数から除外すること |

| 方式 | 同得点時の比較 |
| --- | --- |
| ICPC形式 | 問題ごとのペナルティ時間の合計が小さい方を上位とする |
| AtCoder形式 | 最高得点への到達前のペナルティ対象提出数×n分に、現在の合計得点へ初めて到達した時点の経過時間を加え、小さい方を上位とする |

n=0は誤答ペナルティなしを意味する。得点と選択した比較値が同じ場合は、最後の得点更新時刻による追加比較を行わず、同順位とする。

ここでの2方式はタイブレークの違いを表す。ICPC形式でACした問題数を第一基準にすることは要求しない。
