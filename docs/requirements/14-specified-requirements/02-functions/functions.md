# 機能

## 一般公開・利用者・権限

| ID | 要求 |
| --- | --- |
| REQ-PUBLIC-01 | サービスを一般公開し、非ログイン利用者が公開情報を閲覧できること |
| REQ-REGISTER-01 | 管理者承認なしで登録でき、登録直後にstandard-userとなること |
| REQ-ROLE-01 | [ロール定義](../../../domain/role.md)の機能と操作権限をリリース対象とすること |
| REQ-AUTH-01 | メール認証にマジックリンクを使い、パスワードを使わないこと |

外部認証先の採用範囲と、認証処理をAPI・neoShowcaseのどちらが担うかは未決である。

## 問題・提出・コンテスト

| ID | 要求 |
| --- | --- |
| REQ-CONTENT-01 | 権限に応じて問題・テストケース・judge-definition・解説を作成・管理できること |
| REQ-CONTEST-01 | 通常コンテストとvirtual-contestの作成・運営・参加、Clar、順位の確認を扱うこと |
| REQ-JUDGE-01 | 提出を受け付け、要求キューを介してジャッジを実行し、結果キューから判定・得点を受け取ること。ロール定義に応じた再ジャッジも扱うこと |
| REQ-FILE-01 | 提出ソース本体と作問ファイルをS3へ保存すること。提出ソース本体をDBには保存しないこと |

## 得点と順位

| ID | 要求 |
| --- | --- |
| REQ-SCORE-01 | 問題の得点はWriterが作成したジャッジプログラムの報告によること。各問題の提出の最高得点を採用し、その合計をコンテスト得点とすること |
| REQ-SCORE-02 | 順位はコンテスト得点の高い順とし、同得点時だけ、選択されたタイブレーク方式で比較すること |
| REQ-SCORE-03 | ICPC形式・AtCoder形式の2つをサービス側で用意し、contest-setterが選べること。両方式ともペナルティnを指定でき、nは0以上の整数分で、開始前まで変更できること。開始後は固定とすること |
| REQ-SCORE-04 | 各問題の最高得点を初めて得た提出より前の提出をペナルティ対象とし、CE・IE・WEは回数から除外すること |

| 方式 | 同得点時の比較 |
| --- | --- |
| ICPC形式 | 問題ごとのペナルティ時間の合計が小さい方を上位とする |
| AtCoder形式 | 最高得点への到達前のペナルティ対象提出数×n分に、現在の合計得点へ初めて到達した時点の経過時間を加え、小さい方を上位とする |

n=0は誤答ペナルティなしを意味する。得点と選択した比較値が同じ場合は、最後の得点更新時刻による追加比較を行わず、同順位とする。

ここでの2方式はタイブレークの違いを表す。ICPC形式でACした問題数を第一基準にすることは要求しない。

## メール送信

| ID | 要求 |
| --- | --- |
| REQ-MAIL-01 | マジックリンクのメール送信要求をキューに入れること。配送失敗への専用ハンドリングとアプリケーションによる自動再試行は設けず、利用者が再度送信を要求することで対応すること |
