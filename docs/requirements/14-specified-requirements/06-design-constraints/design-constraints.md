# 設計上の制約

## 実装技術

| 対象 | 現時点の方針 |
| --- | --- |
| WebUI配置 | neoShowcase |
| API・DB・ジャッジ基盤などの配置 | AWSにまとめる |
| 提出ソース・作問ファイル | S3に保存し、提出ソース本体はDBに保存しない |
| ジャッジ要求・結果キュー | SQS |
| DB | PostgreSQL互換を優先。提供サービスは未決 |
| メール認証 | マジックリンク。パスワードは使わない |
| API実行サービス・インスタンス | 未決。後で選定する |

既存実装はWebUIにVue、APIにRust/Axumを使用している。これは現状の技術情報であり、採用製品の追加決定を意味しない。

## 差し替え可能性

基盤を後から差し替えられる構成を要求する。DB・ファイル保管・キューなどの接続箇所と、それぞれが担う責務を分けて把握できるようにする。

具体的な標準スタックは後で調査・選定する。S3・SQSという採用方針が、基盤を永久に固定する要求にはならない。
