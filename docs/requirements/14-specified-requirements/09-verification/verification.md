# 検証

この段階では、要素の責務、接続関係、確定事項とTODOの区別をレビューできることを確認する。数値や方式が未決の要求について、受入条件を確定したとは扱わない。

## 機能要求の確認対象

| 要求 | 確認する内容 |
| --- | --- |
| REQ-PUBLIC-01・REGISTER-01 | 公開情報の閲覧、承認不要の登録、登録直後のstandard-user付与 |
| REQ-ROLE-01 | ロール定義と各操作の権限の対応 |
| REQ-AUTH-01 | マジックリンクによるメール認証と、パスワードを要求しないこと |
| REQ-CONTENT-01・CONTEST-01 | 作問・解説、通常／virtualコンテスト、Clarの対象範囲 |
| REQ-CLI-01〜05 | CLI専用APIを通じた問題登録、トークンの発行・認証・失効、署名付きURLでの直接アップロードと完了通知。DAG・実行環境・ノード結果の解釈情報のメタデータと全テストケース・テストコード・問題得点計算ロジックの受け渡し |
| REQ-JUDGE-01〜04 | 要求・結果の実行IDの対応と再配信・再ジャッジ時の識別。JudgeがDBへ直接接続せず、Backが結果をDBへ反映すること。要求後の問題更新が使用版を変えないこと |
| REQ-JUDGE-05 | 同じ実行IDの同じ結果を再受信しても、得点や結果が二重計上されないこと |
| REQ-JUDGE-06 | ジャッジ定義とジャッジ実行要求を区別し、各実行に対応する提出コードのS3参照・提出言語を受け渡せること |
| REQ-JUDGE-07 | Backが固定した定義と入力の組を渡し、Judgeがそれを実行手順へ具体化できること |
| REQ-JUDGE-08 | オブジェクト参照で指定された提出コードを、Judgeの実行基盤の権限で取得できること |
| REQ-JUDGE-09 | Judgeからノード単位の結果が返り、作問者がCLIから登録した情報に基づいてBackが解釈できること |
| REQ-LANG-01 | UI・CLI・Back・Judgeで言語IDが共通であり、受け付けたIDがそのまま実行時入力としてJudgeへ渡ること |
| REQ-LANG-02 | 問題ごとの禁止言語タグと、言語更新後の過去問題への提出継続。具体的な判定条件はBackのTODOに従う |
| REQ-FILE-01〜02 | S3への保存とWebUIからの直接アップロード、Backによる提出確定・ジャッジ依頼、提出ソース本体をDBに保存しないこと |
| REQ-SCORE-01〜04 | 最高得点の集計、両タイブレーク方式、nの変更条件、ペナルティ対象と除外判定 |
| REQ-MAIL-01 | キューへの送信要求、利用者による再送要求、専用の配送失敗処理・自動再試行を設けないこと |
