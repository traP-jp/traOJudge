# 他の利用者のプロフィールと作成した問題を見る

[シナリオの一覧へ](../../mutation-scenarios.md)

## したいこと

利用者が、他の利用者の公開プロフィールと、その人が作成し閲覧者に閲覧許可がある問題を閲覧する。

## 誰が、誰に、何をしてよいか

| 操作 | 誰が | 誰に／何に・範囲 |
| --- | --- | --- |
| 公開プロフィールを取得する（O3-01） | 誰でも | 指定利用者の表示名、自己紹介、本人申告のGitHub・AtCoder・Xのユーザー名 |
| 作成した閲覧可能な問題を取得する（O3-02） | 誰でも。ログイン時は権限に応じた問題も閲覧できる | 指定利用者が作成者として記録され、閲覧者が閲覧できる問題 |

本人申告のユーザー名は公開情報として扱い、外部サービスとの認証・連携や本人確認済みであることを意味しない。問題一覧は閲覧者の権限で絞る。未ログインでは公開問題だけを返し、ログイン中は `problem-owner`・`tester`・`contest-setter` として閲覧可能な非公開問題も返す。権限のない非公開問題、メールアドレス、役割は閲覧できない。作成者であることと、問題の編集権限（`problem-owner`）は別に扱う。

## 始める前

対象利用者の `userId` が分かっていること。ログインは必須ではないが、ログイン中は自分に閲覧権限がある非公開問題も一覧に含まれる。

## 流れ

1. `GET /api/v1/users/{userId}` で公開プロフィールを取得する。応答には `id`、`displayName`、`bio`、`githubId`、`atcoderId`、`xId`、`revision` を含める。未設定のユーザー名は空文字で返す。
2. `GET /api/v1/problems?createdByUserId={userId}&limit=...` で作成者を指定して問題を検索する。必要なら `query` でタイトルを絞り込み、続きがあれば `nextCursor` を使って次のページを取得する。閲覧権限のない問題は結果に含まれない。
3. 問題を選んだ場合は `GET /api/v1/problems/{problemId}` で問題を取得する。

プロフィールが存在しても閲覧できる問題がない場合は、空の `items` と `nextCursor: null` を返す。プロフィールの `userId` が存在しない場合は `GET /users/{userId}` が404を返す。問題検索では作成者IDに一致する閲覧可能な問題がなければ空のページを返し、非公開問題の存在を知らせない。

問題の `createdByUserId` は作成時にAPIがログイン中の利用者から記録し、あとから変更できない。クライアントに作成者IDを自己申告させない。

## できたと言えること

- 未ログインでも公開プロフィールと作成者の公開問題を閲覧できる。
- ログイン中は、閲覧権限のある非公開問題も一覧に含まれる。
- 閲覧権限のない非公開問題は返さない。
- 本人申告のGitHub・AtCoder・Xのユーザー名を未ログインでも閲覧でき、未設定値は空文字で返す。
- メールアドレスや役割など、公開プロフィールに不要な情報を返さない。
- 作成者情報と問題の編集権限を混同しない。
