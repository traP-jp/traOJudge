# 他の利用者のプロフィールと作成した問題を見る

[シナリオの一覧へ](../../mutation-scenarios.md)

## したいこと

利用者が、他の利用者の公開プロフィールと、その人が作成して公開した問題を閲覧する。

## 誰が、誰に、何をしてよいか

| 操作 | 誰が | 誰に／何に・範囲 |
| --- | --- | --- |
| 公開プロフィールを取得する（O3-01） | 誰でも | 指定利用者の表示名と自己紹介 |
| 作成した公開問題を取得する（O3-02） | 誰でも | 指定利用者が作成者として記録され、公開済みの問題 |

非公開問題、メールアドレス、役割はこの画面から閲覧できない。作成者であることと、問題の編集権限（`problem-owner`）は別に扱う。

## 始める前

対象利用者の `userId` が分かっていること。ログインは必要としない。

## 流れ

1. `GET /api/v1/users/{userId}` で公開プロフィールを取得する。応答には `id`、`displayName`、`bio`、`revision` を含める。
2. `GET /api/v1/users/{userId}/problems?limit=...` で作成した公開問題を取得する。続きがあれば `nextCursor` を使って次のページを取得する。
3. 問題を選んだ場合は `GET /api/v1/problems/{problemId}` で問題を取得する。

プロフィールが存在しても公開問題がない場合は、空の `items` と `nextCursor: null` を返す。存在しない `userId` は404とする。

問題の `createdByUserId` は作成時にAPIがログイン中の利用者から記録し、あとから変更できない。クライアントに作成者IDを自己申告させない。

## できたと言えること

- 未ログインでも公開プロフィールと作成者の公開問題を閲覧できる。
- 非公開問題や本人の編集担当一覧はプロフィールに含めない。
- メールアドレスや役割など、公開プロフィールに不要な情報を返さない。
- 作成者情報と問題の編集権限を混同しない。
