# 人に問題の管理担当を任せる

[シナリオの一覧へ](../../mutation-scenarios.md) · [仕事を任せる・外す話の一覧](change-permissions.md)

## したいこと

サービス管理者（service-admin）が、選んだ問題1つについて、登録済みの人に問題の管理担当を任せる。

## 誰が、誰に、何をしてよいか

| 確かめること | この操作での条件 |
| --- | --- |
| 誰が | サービス管理者（service-admin） |
| 誰に | 役割を任せたい、登録済みの人 |
| 何について | 選んだ問題1つ |
| 何をする | 選んだ人に `problem-owner` を付ける |
| 任せる仕事 | その問題の閲覧・編集・削除、採点のやり直し、採点方法の追加・更新・削除、テスト担当の追加ができる |

根拠は[ロール定義](../../../domain/role.md)の `service-admin`、仕事の範囲は `problem-owner`。

## 始める前

操作する人がログインしていて、上記の立場を持つこと。対象の人と、対象の問題が存在し、どの人のどの範囲を変えるかが決まっていること。

## 流れ

```mermaid
flowchart TD
    A["サービス管理者が対象の人と問題を選ぶ"] --> B["問題の管理担当を任せるよう頼む"]
    B --> C{"サービス管理者か"}
    C -->|はい| D(["選んだ人に、選んだ範囲の問題の管理担当を任せた"])
    C -->|いいえ| E["役割を変えず、変更できない理由を伝える"]
```

## できたと言えること

- 選んだ人に、選んだ範囲の問題の管理担当を任せたことが分かる。
- 別の人や、別の問題の役割を変えない。
- サービス管理者以外が追加できる役割は、テスト担当と通常の大会の運営担当について明記した場合に限る。
- 元の管理担当から役割を外すこととは別の操作。管理担当が必ず1人なのかは未決。

## まだ決めること

- すでに同じ仕事を任せていた人に、もう一度頼まれた場合の扱い。
- 自分自身を対象にする場合の条件と、変更の履歴を誰に見せるか。
- 管理担当の人数、作成直後の担当、担当が0人になる変更の扱い。
