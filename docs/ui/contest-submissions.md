# コンテストの提出一覧

`/contest/:contestId/submissions`に，そのコンテストへ提出された解答を表示する．「すべて」「自分の提出」を切り替えられ，チーム戦ではチームも選べる．問題で絞り込み，カーソルでページを移動する．

## 閲覧範囲と取得先

| 表示範囲       | 取得するAPI                                            | 閲覧条件                                                       |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| すべて         | `GET /contests/{contestId}/submissions`                | 終了前は対象コンテストの作問者．終了後はログイン不要．         |
| 自分の提出     | `GET /me/submissions`                                  | ログイン中の本人．コンテストIDと本人IDで絞り込む．             |
| チーム・終了前 | `GET /contests/{contestId}/teams/{teamId}/submissions` | 現在所属するチーム．作問者は全体一覧から対象チームを抽出する． |
| チーム・終了後 | `GET /contests/{contestId}/submissions`                | ログイン不要．提出に記録されたteamIdで絞り込む．               |

通常大会の終了後は，他人の判定・得点も公開する．`getSubmission`と`getJudgeRun`の認可定義に，通常大会の`endsAt`到達後はログイン不要とする条件を追加した．非公開問題への提出にも同じ条件を適用する．採点履歴を取得する`listJudgeRuns`の権限は変更していない．実APIはサーバー時刻と提出先を使って認可する必要がある．この変更ではバックエンドの処理は実装していない．

問題文を取得できない場合は「問題 D」のように出題ラベルを表示し，提出と判定の取得を続ける．チーム名とメンバーは既存のチーム順位APIから取得する．チーム専用の一覧APIがないため，順位APIに含まれないチームは選択できない．メンバー情報を取得できない場合はチーム表示を止め，再読み込みを案内する．

## 絞り込みと採点の更新

`problemId`，`scope=all|mine|team`，`teamId`をURLのクエリに保存する．問題や表示範囲を変えると先頭ページへ戻る．コンテスト終了時には情報を再取得し，全体表示を開放する．

現行APIの提出一覧には問題で絞り込む引数がない．画面は最大20件ずつ取得し，一致する提出があるページまで読み進める．そのため，画面に並ぶ件数は20件未満になる場合がある．自分の提出の取得では，他のコンテストや大会に紐づかない提出を除く．提出数が増えた場合は，API側への検索条件追加を検討する．

採点中の行は2秒ごとに受付内容と最新のJudgeRunを取得する．同じ採点実行の古いrevisionを捨て，currentJudgeRunIdが変わった場合は新しい採点へ切り替える．採点完了・失敗でポーリングを止める．完了後の再採点や新しい提出は「更新」で取得する．

判定の通信に失敗しても行と最後の進捗を残す．401・403・404は自動再試行を止め，それ以外は再取得する．フィルター変更，ページ移動，画面を閉じた際は通信を中断し，古い応答が表示を上書きしないようにする．バッジの表示は[モックAPIの確認手順](./mock-api.md)と共通である．

## localhostで確認する

[モックAPIの起動手順](./mock-api.md)に従って起動する．

1. [終了済みの個人戦](http://localhost:5173/contest/260b98b4-28de-5c53-8ebc-0f4980b3a0c0/submissions)を開く．ログインせずに，他人の判定・得点と「次へ」「前へ」を確認する．
2. 問題で「D — 問題 D」を選ぶ．非公開の問題文を取得できなくても，その問題の提出結果が並ぶことを確認する．
3. [モックログイン](http://localhost:5173/login)後に「自分の提出」へ切り替える．提出者がモックユーザーの行だけになることを確認する．
4. [終了済みのチーム戦](http://localhost:5173/contest/62bdcafc-4ece-5a05-9a41-b4625c183d12/submissions?scope=team)でチームを選ぶ．チームを変えると，そのチームの提出だけになることを確認する．
5. [開催中の個人戦](http://localhost:5173/contest/3c381dc5-8095-5bb4-9257-bd1e25588c5c/submissions)を開く．ログイン中は自分の提出が初期表示され，「すべて」では終了後に公開する旨が表示される．

初期データは個人戦41件，チーム戦24件，開催中3件，大会に紐づかない提出1件である．AC・WA・TLEを含み，保存済みの結果は取得のたびに変わらない．新規提出の約12秒で完了する採点モックも維持する．

モックはCookieによる認証を再現せず，`me`バケットのユーザーを本人とする．提出一覧・受付内容・判定の一部の認可条件は再現しているが，本番の認証・認可の検証には使えない．

## 検証

`UI/`で`npm test`，`npm run test:mock`，`npm run lint`，`npm run build`を実行する．画面テストでは公開範囲，URLの絞り込み，ページ送り，進捗更新，古い応答の破棄を確認する．HTTPテストでは，終了後の非公開問題の判定取得，開催中の他人の提出への403，自分のチームへの絞り込み，提出と採点IDの不一致への404を確認する．
