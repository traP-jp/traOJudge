# 順位表ページの開発

コンテストの順位表は，個人，チーム，延長戦の3画面を持つ．この文書は画面とMockoonのサンプルを更新する人向けである．Vue Router，生成APIクライアント，Mockoonの基本的な使い方は[コンテストtopの開発](./contest-top.md)を前提とする．最初に「既存契約と仮の応答」を読み，画面確認時は後半のURLだけ参照すればよい．

## 個人・チームの順位と得点は正式APIから取得する

個人戦は`GET /contests/{contestId}/standings`，チーム戦は`GET /contests/{contestId}/standings/team`を使う．[OpenAPI契約](../API/paths/contests.yaml)には，各行の順位，合計得点，タイブレーク値，問題別得点が定義されている．チームの応答にはチーム名とメンバー名も入る．`UI/scripts/gen-contest-api.sh`で生成したクライアントから取得し，表示順を変えても`rank`は書き換えない．問題の並びは`GET /contests/{contestId}/problems`に従う．トグルには大会の`participationMode`に対応する順位表と延長戦だけを表示する．異なる種類の順位表をURLから直接開いた場合は案内を表示し，APIは409を返す．

まだOpenAPIに定義されていない画面情報は，次の仮応答から補う．仮応答の型は`UI/src/types/standings.ts`，取得処理は`UI/src/api/standingsPreview.ts`に置く．正式な契約が決まったら，型とMockoonの応答を更新する．

| 仮の取得口                                         | 画面で使う情報                                       |
| -------------------------------------------------- | ---------------------------------------------------- |
| `GET /contests/{contestId}/standings/details`      | 個人名，AC時刻，凍結状態，問題別の人数，First Accept |
| `GET /contests/{contestId}/standings/team/details` | チームのAC時刻，凍結状態，問題別の人数，First Accept |
| `GET /contests/{contestId}/standings/extended`     | 延長戦の順位・得点・問題別得点・AC時刻，First Accept |

個人・チームの`details`が404の場合も，正式APIで得た順位と得点を表示する．個人名は`userId`で代用する．正式APIでは未提出の問題も得点0になるため，補助情報がない場合は「未提出」と「0点の提出」を区別できない．延長戦の仮応答が404の場合は，データ未提供の案内を表示する．

## 公開時期と凍結を画面で表す

公開大会の個人・チーム順位表は，開催中もログインせずに閲覧できる．非公開大会は対象大会の役割を確認する．延長戦は公開大会でも終了後にだけ開く．開始前の個人・チーム画面には，順位がまだないことを示す．この判定は画面表示用であり，APIへの直接アクセスを防ぐ認可はサーバー側で行う必要がある．個人・チーム順位APIの`x-authorization`にも公開大会の匿名閲覧を記載した．

凍結中は仮応答の`isFrozen`と`frozenAt`を使い，凍結時点の順位・得点と反映待ち件数を表示する．正式APIも凍結時点の値を返さなければ，画面から隠した順位を直接取得できてしまう．大会終了後はモックが最新の順位を返す．現行APIには集計完了を判定する値がないため，画面は「終了」と表示しても「順位確定」とは表示しない．

## Mockoonで3つの状態を確認する

`UI/`で`bash scripts/run-mock-api.sh`と`npm run dev`を実行する．Mockoonの定義は`UI/src/api/mock/front-back-api-mock.json`にある．

| URL                             | 確認できる状態                                     |
| ------------------------------- | -------------------------------------------------- |
| `/contest/260b98b4-28de-5c53-8ebc-0f4980b3a0c0/standings`          | 終了後の個人順位，問題別ソート，検索，First Accept |
| `/contest/62bdcafc-4ece-5a05-9a41-b4625c183d12/standings/team`     | 終了後のチーム順位とメンバー                       |
| `/contest/260b98b4-28de-5c53-8ebc-0f4980b3a0c0/standings/extended` | 全利用者を含む延長戦と同点順位                     |
| `/contest/8e23f1b2-2179-5aeb-9dfe-0f6840f027c9/standings`          | 開始前の空表示                                     |
| `/contest/3c381dc5-8095-5bb4-9257-bd1e25588c5c/standings`          | 開催中の公開大会を匿名で閲覧した場合の凍結表示     |

表の「更新」は表示中の順位表に必要なAPIだけを再取得し，表に反映する．大会情報や問題一覧は再取得せず，ソート，検索，ページ，First Solverの選択状態も維持する．問題別・合計得点のソートは表示順だけを変え，左端には応答に含まれる順位を残す．問題別の昇順では未回答を先頭，降順では末尾に置く．名前またはIDで検索でき，チーム表ではメンバー名も検索対象になる．1ページに10行ずつ表示し，検索とソートは全行に適用してからページを切り替える．サンプルには個人20人，チーム12組，延長戦21人を用意した．大会・問題・利用者・チームのIDは，API定義に合わせてUUID形式に統一している．

仮応答の問題別`acceptedAt`はACした提出時刻を表す．画面ではコンテスト開始からの経過時間に直し，問題別得点の下に表示する．合計得点の下には，問題別のAC時刻で最も遅いものを表示する．これは公式のタイブレーク値とは異なる場合がある．正式APIの`tieBreakValue`は数値だが単位と計算方式の内訳を持たず，AC時刻の代わりには使わない．順位はAPIの`rank`を使う．

表の最下段には「First Solver」を表示する．仮応答の`firstAccepts`に利用者名と`acceptedAt`を持たせ，名前の下に大会開始からの経過時間を表示する．この情報は表示中の行から計算しないため，検索やページ切り替え後も表に残る．名前を押すと検索条件を解除し，該当者のページへ移動してその問題の得点欄を強調する．チーム戦では提出者が所属するチームの欄を強調する．選択状態は画面内で管理し，URLは変更しない．正式APIにはまだFirst Acceptとその時刻の項目がない．
